# Repository instructions

## Clipboard skills

Skip Clipboard `/cb` skills (such as `cb-work`, `cb-ship`, and `cb-review`) in this repository unless the user explicitly requests one. Use the repository's Git and GitHub pull request workflow below.

## Pull requests

- Every change to this repository requires a GitHub pull request, including documentation and changes to these instructions.
- Make changes on a working branch. Commit the changes relevant to the request, push the branch, and open a pull request against the default branch. If the branch already has a pull request for the same work, update it.
- Keep unrelated working-tree changes out of the pull request. Never push changes directly to the default branch.
- Include the pull request link in the handoff. If a permission or tooling issue blocks opening or updating the pull request, report the blocker and what remains.

## Attribution

- Commits and pull requests reference only the repository owner (@git-ebrahim).
- Don't add AI or tool attribution: no `Co-Authored-By` trailers for an AI assistant, no "Generated with Claude Code" (or similar) lines in commit messages, pull request titles, or pull request descriptions.
- Squash merges use the pull request title and description as the commit message, so keep descriptions free of attribution too.
